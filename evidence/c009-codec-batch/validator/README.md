# Validator — C009 comparison script

`c009_compare.py` recomputes every comparison number in `../results/comparison.json`
from the raw per-request records and the retained WAV files.

## Dependencies

Python 3 standard library only (`hashlib`, `json`, `pathlib`). It does not import
`torch`, `torch_npu` or any project module, so it runs on any host that can read the
two result trees.

## Where it runs

It is written against the A2 layout and therefore must run where those paths exist
(inside container `zc-qwen3-tts-cpp-20261019`, or on the A2 host with the trees
copied to the same absolute paths):

- reads `/work/c009/results/codec4/<arm>/c<cohort>/results.json` and `*.wav`
- reads `/work/c009/results/codec8/<arm>/c<cohort>/results.json` and `*.wav`
- writes `/work/c009/results/comparison.json`

```
docker exec zc-qwen3-tts-cpp-20261019 bash -c \
  'cd /work/c009 && /work/venv/bin/python scripts/c009_compare.py'
```

The same command line was used to produce `comparison.json`; its exit status was
captured to `logs/compare.exit` (= 0) and its stdout to `logs/compare.out`.

## What it proves

For each arm (`r1-native` inline, `r1-reference` buffered) and cohort (16/32/64) it
compares, per index: `pcm_sha256`, the WAV file SHA256, and `codec_frames`; it
recomputes throughput as `sum(audio_seconds) * 12.5 / wall_seconds` and reports the
delta against the reported `throughput_frames_s` as a defect if non-zero. It never
reads `assessment.json`.

## Repo copy versus A2 copy

This file is the repository copy. The A2 copy lives at
`/work/c009/scripts/c009_compare.py`; both were produced from the same source, and
`results/comparison.json` was generated by the A2 copy before this file was added to
the repository.
