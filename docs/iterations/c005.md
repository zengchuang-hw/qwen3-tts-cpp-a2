# C005: adaptive paired rotary tiling

Prior [RFC #10](https://github.com/zengchuang-hw/qwen3-tts-cpp-a2/issues/10)
precedes [PR #11](https://github.com/zengchuang-hw/qwen3-tts-cpp-a2/pull/11).
Only the head tile changes: 4/8/16, same FP32 pointwise operations, fusion disabled,
final BF16 output, bounds and layout checks. Default remains4.

The selection experiment at commit52e15d8064268c8acefadf8d2013fbad3dd16adb
on physical910B3 device3 passed320 exact graph-replay checks, including changed
inputs/coefficients, D64/128, B1/4/16/32/64, L1/2 and both coefficient layouts.
L1 uses32-call hot-input graphs,32 timed replays,3 samples after10 warmups;
these are operator measurements, not end-to-end performance.

Frozen before full-model runs: auto selects16 only for D128, B>=16, L1/2;
otherwise4. At B16/32/64 the selected mean pair latency reductions against4
are45.17/57.03/61.74% for L1 and57.03/61.96/64.45% for L2 (full raw values
retained). Tile8 is slower than16 at these points. Small batches keep4 as
predeclared; no retrospective expansion from other favorable microbench points.
RMS fusion and precision changes remain outside scope.

Use --predictor-rope paired --rotary-head-tile auto through serve.py, probe.py,
campaign.py or qtts. Explicit4/8/16 are available for comparison. Nondefault tile
settings require the paired path. Graph captures retain the selected constants.

campaign.py --reference-engine native-tile4 compares the same source and audio
mode against fixed4. It cannot yield an upstream acceptance PASS. Upstream mode
retains its fixed command and all seven-concurrency gates. Full WAV/stream parity,
state/CLI and both causal/upstream pilots are required by the RFC. Defaults are
not promoted based on L1; full formal acceptance remains separate.
