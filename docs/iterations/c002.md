## Mechanism and alternatives

Replace the predictor's separate native Q/K rotary calls with one Triton Ascend
kernel. It uses FP32 products and sums followed by BF16 output, four heads per
tile, and a grid bounded by vector cores. Q16/K8, head dimensions 64/128,
lengths 1/2 and shared/per-request coefficients are operator-qualified. The actual
model predictor uses head dimension 128. The rest of attention stays unchanged.
Select with `--predictor-rope paired`; `native` remains the default and control.

A separate B4 diagnostic trace suggested rotary as an optimization target:
2,400 native rotary calls across 16 frames, 22,507 us summed kernel time. The
profiler emitted a RECORD-stop warning; these are diagnostic accounting numbers,
not critical-path attribution or throughput measurements.

Alternatives:

- Retain native rotary: supported as the control and default.
- Pair Q/K into one launch: selected to reduce operator dispatch, with exact
  native arithmetic checked before speech comparison.
- BF16-round each intermediate product: tested counterexample; differs from
  native output and is rejected. It is not silently used as a faster variant.
- Change attention algorithm or quantize weights: deferred to keep one numerical
  mechanism isolated; no such speed or quality claim is imported.

Also guard source, both binaries, packages, Python, libc6/libstdc++6, CANN install
identity, relevant environment variables and all 11 pinned model assets before
and after every arm. Drift aborts rather than producing qualified results.
Reject public requests exceeding the allocated native output arena before
enqueueing them. These changes address weaknesses observed in C001.
